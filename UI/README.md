# Altair UI

Build.lua contains interface construction and embedded assets. Altair.lua loads and binds it. No uploaded Roblox UI is required. Lua construction does not make Altair network-free: thumbnails, artwork, remote modules and selected scripts or features can still make network requests.

Repeated runs reuse compiled Build code when its complete source, compiler and execution environment match. Each run still evaluates a fresh module and constructs a new interface; changing the source invalidates that cache. Disabled OLED idle dimming skips colour capture. Enabling it captures and updates colours in bounded work slices.

General contains colour, tint, lightness, opacity and sizing controls. Altair uses one interface layout; removed style selections are ignored. Experimental groups Movement Detection, Chat Detection, Detection Feedback, Game UI Avoidance, Capsules, and Spotify. Each section is marked experimental; bugs are to be expected. HUD avoidance uses bounded native hit tests only during dragging; hidden widgets and large full-screen backgrounds are excluded. Newly appearing widgets and very fast movement may precede the bounds cache.

General's Server Region Lookup is off by default. While OFF, this feature uses an experience-provided region when available and does not start server-IP discovery or geolocation requests. Enabling it permits discovery of the game-server IP and requests to ipapi.co; that provider also sees ordinary connection metadata, including the connection IP. Already sent requests cannot be recalled. This setting does not control other Altair networking.

Notifications: Altair.notification(title, description). Notify and QueueNotification are compatibility aliases. UI size defaults to 110%.

Smartbar buttons have small palette-linked rules above and below the icon. Opening a panel expands and brightens its rules with a brief icon spring; closing retracts them. Section markers and Settings category dividers follow the existing button/category gradients, including custom colors and rainbow changes. This event-driven accent layer does not change dock geometry or add an idle render loop.

Settings search matches names, descriptions, preference IDs and related keywords. Select a result to open its category and scroll to the control. Hidden settings and private Developer controls stay excluded; saved values are never indexed. Arrow keys select results, Enter opens one, and Escape clears the search.

Existing detection preferences keep their saved IDs after moving from Detections. Movement signals include sustained flight/hover, excessive ground-relative speed and persistent spinning physics; repeated teleports and airborne lifts are optional. Seat, swim, climb, spawn, ordinary-jump and replication-gap exclusions reduce incidental signals. Game abilities, vehicles, lag and knockback can produce similar observations. Movement and chat checks are experimental local signals, not proof that another player is cheating.

Chat detection combines sustained repetition, bursts and repeated links with content patterns, using only messages this client receives. Bounded recent history retains pattern hashes rather than message transcripts. Detection Details and Detection Cooldown control alert feedback; Detection Status shows active checks, counts and recent movement revisit timing, and Clear Detection History clears evidence. Detection Self Test is nonpersistent and includes your own existing movement and received chat for the current run only; a fresh run starts with it off. It does not move your character, send messages, kick players or file reports.

Movement sampling uses the existing worker with bounded batches; no detector render loop or per-player worker is added. Player count, frame budget and lag affect revisit times and alert latency. New teleport corrections are evaluated only across revisit gaps of 1.2 seconds or less. Detection Status timing is a recent sampling snapshot, not a guarantee of player coverage or detection latency.

Scripts → Built-in tools provides native Free Camera and Fullbright, plus the existing populated-server hop, rejoin and clipboard actions. Free Camera uses WASD, Q/E, right-mouse look and Shift for faster movement. Camera bindings exist only while enabled; stopping restores the owned camera pose and controls while preserving newer FOV/subject changes. Fullbright restores lighting properties it still owns. `Altair.ListNativeTools()` lists the catalog; `Altair.RunNativeTool(id)` runs an entry. Unloading releases utility input and restores owned state.

Rayfield compatibility targets the inspected Gen2 1.2.3 window API, not every Rayfield version or window. Appearance inheritance requires a recognized window API and the bridge's 47-field default-theme check to pass. Explicit palette/custom-theme changes opt out; compatible font-only updates remain supported. Disabling capsules restores the original pill and original theme values where the bridge still owns them. Unloading restores owned methods and appearance; unsupported APIs and custom palettes are not automatically themed. Theme changes animate without an idle polling loop.

Spotify instructions: ../Companion/README.md. Licences: ../THIRD_PARTY_NOTICES.md. Modified component source is embedded in Build.lua.

Tests and developer implementations are excluded from the public tree. The Developer tab appears only if Volt workspace contains Altair/Developer/AltairDevTools.lua. No inline source override is accepted.

Rainbow mode also animates coloured card/capsule gradients, accents, outlines and coloured glyphs. White/black foregrounds, artwork and semantic status indicators are preserved. Only visible registered accents update at the existing capped 20 Hz rate; the selected colour palette is restored when disabled.

Altair service status uses [Sentivel](https://www.sentivel.com/status/altair-cloudz) public badges for the runtime and interface download components. Each poll cycle can request one badge per component (currently two requests); cycles are throttled to at least five minutes, with cached poll reservations retained across reruns. These report configured download-monitor health, not per-player monitoring or proof of successful execution in every game. Requests add no player/account fields or account credential, but the status host still receives ordinary connection metadata, such as the connection IP. Initial healthy/unknown states stay quiet; reported service issues and confirmed recoveries use normal Altair notifications. Cached status and announcement state persist across reruns. Network failures mark status unknown without inventing an outage or recovery.
